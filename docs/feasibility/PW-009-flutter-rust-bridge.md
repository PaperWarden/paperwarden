# PW-009: Flutter-Rust bridge feasibility

**Issue:** #12  
**Date:** 2026-11-26  
**Result:** Feasible on Android, proven locally and in CI. iOS is proven in CI
only (macOS runner); no local iOS run was possible from the Windows machine.  
**Decision record:** ADR-0005 (Proposed)

## What was built

- `core/crates/bridge` (`paperwarden_bridge`): a workspace member exposing a
  deliberately small probe API through flutter_rust_bridge 2.13.0.
- `CancellationToken` in `paperwarden-core`: the cancellation primitive jobs
  will use, independent of the bridge.
- `apps/mobile/rust_builder`: the Cargokit build plugin generated by
  `flutter_rust_bridge_codegen integrate`, trimmed to Android and iOS.
- `apps/mobile/lib/src/rust`: generated Dart bindings. `main.dart` loads the
  library before the first frame.

The probe API processes no documents. It exists to prove each criterion below
and is replaced by real job APIs in #33.

## Criteria

| Criterion | Evidence | Result |
| --- | --- | --- |
| Synchronous calls | `coreVersion()` returns the core version without a `Future` | Pass |
| Asynchronous calls | `runProbeJob` runs ~400 ms on a Rust worker thread; a Dart timer keeps ticking throughout | Pass |
| Cancellation | Dart cancels a 10 s job after 50 ms through an opaque `CancelHandle`; it stops in under 2 s with `BridgeErrorKind.cancelled` | Pass |
| Errors | Out-of-bounds arguments and core `JobId` rejections reach Dart as a typed `BridgeError` exception | Pass |
| Generated-binding reproducibility | Regenerating locally produces no diff; the new `Bridge` workflow regenerates in CI and fails on any diff | Pass |
| Android build | `flutter build apk` cross-compiles the crate with the NDK; the APK carries `libpaperwarden_bridge.so` for every ABI; CI asserts it | Pass |
| iOS build | `ios.yml` builds for the simulator with the Rust targets and asserts the bridge symbols are linked into `Runner.app` | CI only |

On-device evidence: `flutter test integration_test/bridge_test.dart` passed
5/5 on the `PaperWarden_API_35` emulator (x86_64), and the full app launched
with the library loaded and no load errors in logcat.

## Supply chain

flutter_rust_bridge is built with `default-features = false` and only
`dart-opaque`, `rust-async` (needed by opaque types) and `thread-pool`. That
removes logging, backtrace, anyhow and wasm-start, and cuts the Rust
dependency graph from 84 to 64 crates. All are permissive (MIT, Apache-2.0,
BSD, Zlib, Unicode-3.0). `cargo deny` and `cargo audit` pass, and every crate
is recorded in `third_party/dependencies.json`.

`scripts/check_licenses.py` was strengthened along the way:

- Packages are keyed by name **and version**. Before, two locked versions of
  one crate (here `syn` 2 and 3) collapsed into one entry, so one version went
  unchecked.
- Duplicate inventory entries are rejected.
- `A AND B` license expressions are accepted only when every term is allowed.
  OR expressions must be recorded as the elected license, with the original in
  `declared`.

## Findings and risks

1. **Cargokit fails silently on a name mismatch.** It looks for
   `lib<package-name>.so`. With the package named `paperwarden-bridge` it built
   the crate, found no `libpaperwarden-bridge.so`, and shipped an APK without
   the library; the app then failed only at launch. Fixed by naming the package
   `paperwarden_bridge`, and guarded by the CI check that the APK contains the
   library for each ABI.
2. **Cargokit's build tool resolves Dart packages at build time without a
   lockfile.** Its `build_tool` pins versions in `pubspec.yaml` but runs
   `pub get` on every clean build, and it depends on `http` for an optional
   prebuilt-binary download. Prebuilt binaries are disabled (the build log
   says so), so nothing is downloaded and the app never contains this code.
   The build itself still needs pub.dev. Track this before release builds are
   made reproducible.
3. **The generated module needs lint exceptions.** The generated FFI glue is
   unsafe and contains an unreachable `unimplemented!`. The bridge crate
   cannot inherit `unsafe_code = "forbid"`, so it sets `deny` and allows the
   exceptions on the generated module only, with a stated reason. Hand-written
   bridge code follows the same clippy policy as the core.
4. **Cargokit is vendored code.** It lives in `apps/mobile/rust_builder/cargokit`
   (MIT), is excluded from `flutter analyze`, and is not edited. Upgrading
   flutter_rust_bridge means regenerating it with `integrate`.
5. **Disk use.** Android Rust builds for four ABIs need several GB. The first
   local build failed on a full disk.

## Follow-ups

- Add the `Bridge` workflow's `bindings` check to the required status checks.
- Cache the `flutter_rust_bridge_codegen` install in CI (about 5 minutes

- Measure call latency with the first real API.
