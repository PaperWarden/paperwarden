# Corpus

Keep small, redistributable, reviewed fixtures grouped by behavior rather than by
where they came from.

- `valid/<format>/`: minimal valid files and edge cases.
- `malformed/<format>/`: truncated, inconsistent, or otherwise invalid structures.
- `security/<format>/`: inert fixtures for traversal, active content, remote
  references, entity expansion, decompression and dimension bombs, nesting and
  parser loops.
- `conversion/<source>-to-<target>/`: an `input.*` and the text or cells the
  output must contain.
- `ocr/`: rendered text images and their ground truth.

Formats are `pdf`, `office`, `archive`, `image`, `text`, `html` and `svg`. The
three original fixtures at the top of `valid`, `malformed` and `security`
predate this layout and stay where they are.

Never include real private documents, live credentials, functional malware, or
unreviewed third-party copyrighted material. Each fixture needs provenance,
license, purpose, and an expected result.

## Generated fixtures

Every fixture except the original three is generated by
`scripts/generate_corpus.py`, so all are CC0-1.0 with known provenance. Security
fixtures contain the structure a parser must refuse, never working malware:

- Scripts are comments, and the macro part is placeholder text, not VBA.
- Remote references use the reserved `.invalid` domain, which never resolves.
- Bombs are bounded: 16 MiB decompressed, 3 x 10^8 characters of entity
  expansion, or a declared 100,000 x 100,000 image.

After changing a fixture, edit the generator, run it, and review the diff in
both the fixture and `manifest.json`. `python scripts/generate_corpus.py
--check` reports fixtures whose bytes would change. Compressed output depends
on the zlib and Pillow builds, so a rerun elsewhere can change bytes without
changing meaning; the committed files are authoritative. JPEG, WebP, TIFF and
the OCR images need Pillow 12.2.0.

`expected` describes what a correct engine must do. No engine exists yet, so
these are targets, not passing results: a fixture does not make a format
supported (`PRODUCT_INVARIANTS.md` 12, `SUPPORTED_FORMATS.md`). Where a claim
cannot be checked without an engine, such as Office viewer acceptance or OCR
accuracy, `expected` says so.

`manifest.json` is authoritative (schema 2). Besides hashes, licenses and
provenance, each entry records its category, format, expected outcome, the
engine capability it needs, and structural facts that CI verifies against the
bytes. [docs/ci/corpus.md](../../docs/ci/corpus.md) defines the schema, what CI
proves, the contract for engine runners, and artifact retention.
